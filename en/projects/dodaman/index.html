Distance

Inside the cube

Overview

Distance connects people who want to do the same thing at the same time — read, run, grab a coffee — with others close by. The Flutter web client is live; the Go backend is being built underneath it.

Problem

Wanting to do something and having someone nearby to do it with rarely line up. Social apps are built around existing contacts, not around an activity and a place right now.

Approach

Three steps, mirrored in the onboarding: choose what you feel like doing, see people and places for it on a live city map, then join, propose a time in chat or post your own invite.

Architecture

A Flutter client shared across web and mobile talks to a Go backend service. I designed the initial architecture and implemented the service bootstrap and its /health endpoint.

Technical decisions

Go for a small, fast, easily containerized backend; Flutter to ship one codebase to every platform; a Docker-first workflow on Linux/WSL2 so the backend runs the same on every machine.

Challenges

Keeping backend execution reproducible across environments from day one, and defining a development and deployment path that grows with the app instead of being rebuilt later.

Results

A published web client with the full onboarding flow, and a containerized backend foundation ready for the matching, map and chat features.

Dodaman

Document Dashboard Management

Inside the cube

Overview

Built while working at Universidad Nacional de Colombia (May 2024 – June 2025): a dashboard where researchers store, describe and share documents, and administrators control who can see and do what. I started it before AI tools were as capable as they are today, so I worked through most of it on my own — which made it a great opportunity to learn a lot.

Problem

Research documents were sensitive and scattered, with no single place to manage them, attach metadata or control access per person and per document.

Approach

A React and TypeScript dashboard on top of a REST API that owns routing, authentication and authorization, with registration gated by validation and administrative approval.

Architecture

A monorepo shares types and validations between frontend and backend so both sides agree on every payload. The whole project is containerized with Docker, and users get real-time notifications.

Technical decisions

Granular roles plus document-specific permissions instead of a flat admin/user split; shared validation code to avoid drift; Docker to make development and deployment identical.

Challenges

Protecting sensitive user data: personal information is encrypted before it is stored and validated at every step of registration. On top of that, permissions had to be flexible enough for real research groups without becoming unmanageable.

Results

A working system with metadata, encrypted user data, permissions, approval flows and an analytics view, now available as a public demo with an administrator account. Building it largely without AI gave me a solid grounding in authentication, data protection and full-stack architecture.

04 /Case study

LCDR

La Catedral del Reino

Inside the cube

Overview

A fast, content-first website for a Spanish-speaking church in South Florida, giving visitors everything they need before their first Sunday.

Problem

The church needed one clear place for service times, both campuses, its ministries and upcoming events — and a simple way for people to ask for prayer or get in touch.

Approach

A homepage that answers “when and where” immediately, then walks through the vision, six ministries, events and a prayer-request call to action, with directions to each campus.

Architecture

Built with Astro and deployed on Cloudflare. Pages ship as static HTML, and the interactive parts are React islands: the only places where JavaScript is loaded.

Technical decisions

I chose Astro for speed: instead of shipping a full single-page app, the site only loads JavaScript in the islands that use React, so it loads fast on any phone. Visually, a dark, editorial style with a single warm accent for calls to action.

Challenges

Keeping a lot of community information — two campuses, ministries, events, donations — easy to scan for first-time visitors on mobile.

Results

A live production site at lcdr.church that the church uses as its main public presence.
